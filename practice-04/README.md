## Эксперименты с формой и JSON

| Опыт | Прогноз | Наблюдение и причина |
|---|---|---|
| Пустое обязательное название | `submit` не происходит | Нативное `required` блокирует отправку; обработчик не вызывается. |
| Название из пробелов | HTML пропускает, прикладная проверка отклоняет | После `trim()` строка пуста; выводится ошибка через `setCustomValidity`. |
| Корректная отправка | `FormData` содержит строки | `submit.defaultPrevented` равен `true`, название очищается по краям. |
| Чтение записи | `getItem` возвращает строку | `JSON.parse` восстанавливает объект `{ title, priority }`. |
| Повреждённый JSON | Разбор выдаёт исключение | `try/catch` показывает управляемую ошибку; приложение использует исходный набор. |

Эксперименты используют отдельный ключ `tip-js-practice-04:lab`, поэтому не меняют задачи приложения.

## Форма и хранение

`validateTaskDraft` отклоняет пустой, повторный и небезопасный id; название вне 1–100 символов после `trim`; неизвестный приоритет. В режиме редактирования id берётся из `editingId`, поле id блокируется, а `completed` сохраняется. Штатные модульные проверки подтвердили все эти случаи, включая неизменность входного списка.

Сохраняется `{ version: 1, tasks }`. Общий и индивидуальный наборы используют разные ключи: `tip-js-practice-04:demo` и `tip-js-practice-04:variant`. Запись отсутствует — загружается независимая копия исходных задач; корректная запись восстанавливается; неверная версия, схема или JSON дают исходный набор и предупреждение. Сброс удаляет только текущий ключ, не вызывает `localStorage.clear()` и не записывает исходный набор снова.
